# TreaSurv 전체 코드 · 개선판

기존 「스타트업 자금운용 AI 구상」의 Streamlit, 흰색·보라색, TS 로고, 가태용, 가상 연결 데이터 콘셉트를 바탕으로 만든 독립 실행 버전입니다.
기존 프로그램 폴더에 덮어쓰지 말고, 이 폴더를 새로 열어 실행하세요. 필요한 파일이 모두 포함되어 있어 이전의 components/views 폴더를 가져올 필요가 없습니다.

## 1. 실행

Python 3.11 또는 3.12가 설치된 환경을 권장합니다. ZIP을 압축 해제하고 **이 README가 있는 TreaSurv 폴더**를 VS Code에서 여세요.
터미널에서 아래 명령을 순서대로 실행합니다. `python` 명령이 없다면 `py`로 바꿔 실행하세요.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

브라우저에서 http://localhost:8501 에 접속하고 **데모 시작하기**를 누르세요.
다음부터는 마지막 명령만 실행하면 됩니다. 이 버전은 로컬 서버가 켜져 있어야 접속할 수 있습니다.

## 2. Groq 연결

API 키 없이도 모든 계산·시나리오·보고서 기능이 실행됩니다. AI CFO는 키가 없을 때 고정된 로컬 계산 요약을 제공합니다.

1. `.env.example`을 복사해 같은 폴더에 `.env`로 저장합니다. 기존 `.env`가 있다면 키 항목만 직접 옮기세요.
2. `.env`에 다음 값을 설정합니다.

```text
GROQ_API_KEY=본인의_API_키
GROQ_MODEL=llama-3.3-70b-versatile
```

3. 서버를 다시 실행합니다.
4. **설정 → Groq AI 사용**을 켭니다.
5. AI CFO에서 질문합니다. 키는 대화창에 붙이지 마세요.

Streamlit Cloud에서는 `.streamlit/secrets.toml`에 대응되는 Secrets 설정을 사용합니다. `.env`와 secrets 파일은 GitHub에 올리지 마세요.
API 연결이 켜지면 질문·최근 대화·집계 재무 수치·사업계획을 Groq로 전송합니다. 이 패키지에는 API 키가 없습니다.

## 3. 시연 순서

1. 대시보드: 가용 현금 → 보호할 현금 → 운용 상한 → 추가 수익 가정.
2. 데이터 연결: 가상 잔액과 월 현금유입·지출을 수정.
3. 사업계획: 채용·장비·매출 증가·자금조달 추가. 채용 금액은 추가되는 **월 총인건비**입니다. 매월 지출이면 반복을 체크합니다.
4. 시나리오 비교: 조달 지연·매출 감소·비용 증가를 변경.
5. 보호할 현금: 목표 기간과 예비자금 설정.
6. 운용 시뮬레이터: 운용 비중, 기존·비교 연이율, 기간을 적용하고 정책 초안 생성 → 데모 승인.
7. AI CFO: “투자유치가 3개월 늦어지면?” 또는 “3개월 후 월 총 1,200만 원의 확정 채용계획을 제안해 줘.”
8. AI 계획은 화면의 **계획에 반영** 버튼을 눌러야 실제 데모 데이터에 반영됩니다.
9. 보고서에서 Markdown·CSV·데이터 백업 JSON 다운로드. 백업 JSON은 같은 화면에서 복원.

## 5. 계산의 의미

- 모든 원본 금액은 **원** 단위, 입력 화면은 **만 원** 단위입니다.
- 가용 현금 = 총 현금 − 사용 제한 자금.
- 보호할 현금 = 목표 기간의 최대 누적 부족액 + 현재 월 지출 × 예비 개월 수.
- 보호 기준에서는 매출 감소·비용 증가를 반영하며, 미수령 자금조달과 미확정 추가 매출을 제외합니다.
- 운용 상한 = max(0, 가용 현금 − 보호할 현금).
- 선택 운용액 = 운용 상한 × 배분 비중.
- 기간 이자 = 선택 운용액 × 입력 연이율 × 개월 / 12.
- 추가 수익 = 같은 원금을 기존 이율로 보관했을 때와의 차이. 확정 수익·검증된 수익률이 아닙니다.
- 원금이 유지되고 이자를 만기에 받는 단리 가정입니다. 세금·수수료·중도해지·상품 가격변동을 계산하지 않습니다.
- 현금 전망 차트에는 운용수익을 중복 합산하지 않습니다.
- 월별 모델이라 월중 입금·출금 순서에 따른 일시 부족을 검증하지 않습니다.
- 데이터 변경은 과거 정책 승인을 새 입력에 대해 무효로 표시합니다.

## 6. 데모의 범위

실제 로그인, 은행 연동, 매매·송금, 영구 DB, 실제 권한 통제는 포함하지 않습니다. 팀은 가상의 관리자 한 명입니다.
데이터·승인·로그·채팅은 Streamlit 브라우저 세션 안에 유지됩니다. 연결 종료나 서버 재시작 시 사라질 수 있으므로 보고서 화면에서 JSON으로 백업하세요. 백업은 입력값과 계획만 포함하며, 승인·채팅·로그는 복원하지 않습니다.
특정 금융상품을 추천하거나 현금 부족 확률을 산출하지 않습니다. 계산 엔진은 설명 가능한 결정론적 데모이며, 금융 모델로 검증되었다는 의미는 아닙니다.

## 7. 검증

```powershell
.\.venv\Scripts\python.exe -m unittest test_finance test_ui test_agent -v
```

13개 메뉴 실행, 계획 추가, 정책 승인, 데이터 변경 후 재승인 표시, 보호 현금 유지, 조달 제외, 월별 반복·조달 지연, 잘못된 입력 거부, 단리·추가 수익 계산을 검사합니다.
실제 Groq API 호출은 본인 키를 설정한 뒤 확인해야 합니다. 키 없는 로컬 모드와 도구 연결 코드는 포함됩니다.
